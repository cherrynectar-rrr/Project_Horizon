# Two Pointers — 双指针

[← 返回 Block 01](../README.md)

## 1. 本课概览

这一课继续利用“升序有序”这个结构，但不再每次跳到中间。

我们解决的问题是：

> 在一个升序数组中，是否存在两个不同位置的数，它们的和等于 `target`？

最直接的方法可以枚举所有数对，但那会产生大量重复尝试。

当前课程使用两个指针：

```text
left  → 从最小值开始
right → 从最大值开始
```

根据当前两数之和与 `target` 的大小关系，只移动真正有可能改善答案的那个指针。

本课真实实现最终返回 `true / false`，最坏时间复杂度 `O(n)`，辅助空间 `O(1)`。

> 注意：本课学习的是“升序数组 two-sum”这一种双指针模式。并不是所有双指针问题都要求数组有序。

---

## 2. 直觉 / Intuition

升序数组：

```text
[1, 3, 4, 6, 9, 11, 15]
```

假设：

```text
target = 13
```

先取两端：

```text
1 + 15 = 16
```

和太大。

这时候如果把 `left` 向右移动，左边的数只会变大，和不但不会变小，反而可能更大。

所以真正有意义的动作是：

```text
right--
```

让右边的数变小。

如果当前和太小，则反过来：

```text
left++
```

因为 `right` 已经是当前能选到的最大值，再把 `right` 左移只会让和更小，不可能帮助我们达到更大的 `target`。

这就是本课真正需要理解的地方：

> **指针怎么移动不是规定出来的，而是由有序性和当前结果共同推出来的。**

---

## 3. 核心思想 / Core Idea

初始化：

```text
left = 0
right = n - 1
```

只要：

```text
left < right
```

就还有两个不同位置可以组成一对。

计算：

```text
sum = nums[left] + nums[right]
```

然后分三种情况。

### `sum == target`

找到答案：

```cpp
return true;
```

### `sum < target`

当前和太小。

因为数组升序，想让和变大，需要让较小的一端变大：

```cpp
left++;
```

### `sum > target`

当前和太大。

想让和变小，需要让较大的一端变小：

```cpp
right--;
```

每移动一次指针，都永久排除了一批不可能成为答案的组合。

## 4. 手推 / Hand Simulation

数组：

```text
[1, 3, 4, 6, 9, 11, 15]
```

目标：

```text
13
```

### 第 1 步

```text
left  = 1
right = 15
sum   = 16
```

`16 > 13`，和太大：

```text
right--
```

### 第 2 步

```text
1 + 11 = 12
```

`12 < 13`，和太小：

```text
left++
```

### 第 3 步

```text
3 + 11 = 14
```

`14 > 13`：

```text
right--
```

### 第 4 步

```text
3 + 9 = 12
```

`12 < 13`：

```text
left++
```

### 第 5 步

```text
4 + 9 = 13
```

找到答案：

```text
true
```

整个过程没有枚举所有数对，而是不断利用“太大 / 太小”的信息缩小可能范围。

## 5. 实现 / Implementation

本课真实代码：[`main.cpp`](./main.cpp)。

```cpp
bool hasTwoSum(const std::vector<int>& nums, int target)
{
    int left = 0;
    int right = nums.size() - 1;

    while (left < right)
    {
        if (nums[left] + nums[right] == target)
        {
            return true;
        }
        else if (nums[left] + nums[right] < target)
        {
            left++;
        }
        else
        {
            right--;
        }
    }

    return false;
}
```

### 为什么是 `left < right`？

题目需要两个不同位置。

如果：

```text
left == right
```

两个指针已经指向同一个元素，不应该把同一个位置使用两次。

### 为什么只移动一个指针？

当前比较只告诉我们“和太大”或“和太小”。

根据有序性，我们能够确定哪一个方向一定没有帮助，于是只排除那一侧。

如果两个指针同时移动，就可能跳过本来存在的答案。

---

## 6. 复杂度 / Complexity

`left` 只能向右移动。

`right` 只能向左移动。

每个指针在整个算法中最多走过数组一次。

因此虽然有一个 `while` 循环，整体移动次数仍然只与 `n` 同数量级：

```text
O(n)
```

算法只维护：

```text
left
right
以及当前比较需要的固定状态
```

所以辅助空间：

```text
O(1)
```

与朴素枚举所有数对常见的 `O(n^2)` 相比，这个模式利用有序性把搜索降到了线性级别。

## 7. 常见错误 / Common Mistakes

### `sum < target` 时移动 `right`

`right` 当前已经指向较大的数。

把它左移只会让和更小，更不可能追上更大的 `target`。

所以应该：

```text
left++
```

### `sum > target` 时移动 `left`

把左指针右移会让左侧数变大，和通常只会更大。

所以应该：

```text
right--
```

### 每轮两个指针一起移动

这样没有利用比较结果提供的信息，还可能直接跳过答案。

### 忽略有序前提

本课的移动理由依赖升序结构。

如果数组无序，不能仅凭当前和的大小判断哪一侧应该移动。

### 循环写成 `left <= right`

当前任务需要两个不同元素，因此指针相遇时就应该停止。
