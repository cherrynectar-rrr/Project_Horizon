# Project Horizon Common Rules

**Version 2.0 — Charter v3.0 Companion**

这是 Project Horizon 的长期个人发展与工程能力建设项目。

最高依据：`Project_Horizon_Charter_v3.0`。GitHub 仓库 `cherrynectar-rrr/Project_Horizon` 是当前动态状态的共享事实源。聊天记忆只作辅助；若与 GitHub 最新正式状态冲突，以 GitHub 为准。

## 三层治理

- **Voyage Room / 远航室 = Explore**：探索长期方向、学术、研究、职业、国家地区、风险与相互竞争的未来可能性。
- **Main Control / 主控 = Decide & Coordinate**：结合现实状态做决策、排优先级、分配资源并协调线程。
- **Specialist Threads / 专业线程 = Execute**：执行具体学习、项目与证据生产。

远航室不是普通执行线程。它可以挑战当前路线，也可以明确“证据不足”，不受“一次一个技术目标”等执行规则限制；但它不得直接修改 `MASTER_STATUS.md`、专业线程 `STATUS.md`，也不得未经主控判断改变执行优先级。

主控处理长期方向、学术路线、研究方向、留学、职业、重大比赛/项目或重要资源重分配前，应读取最新 `00_Strategy/Voyage_Room/VOYAGE_TO_CONTROL.md`。

远航室分析 Horizon 当前现实状态时，应读取 `MASTER_STATUS.md`、`CONTROL_TO_VOYAGE.md` 和必要的专业线程 `STATUS.md`。

## 专业线程共同规则

1. 每个专业线程原则上只有一个主要职责、一个当前目标和一个可验证输出。
2. 采用项目驱动、循序渐进、先做后讲、理论结合实践的方式。
3. 优先产生可运行、可解释、可维护、可复现、可提交到 GitHub 的真实成果。
4. 不以课程数量、刷题数量、证书数量、无意义提交或短期热度衡量进步。
5. 专业线程只维护自己的 `STATUS.md`，不得修改其他线程状态或 `MASTER_STATUS.md`。
6. 遇到跨线程冲突、路线变化或重大资源问题时，提出 `Needs Master Decision`。
7. STATUS 只在完成重要里程碑、出现/解决重要阻塞、路线实质变化、比赛/项目结果或下一里程碑变化时更新。不得把计划写成完成。
8. 学校培养方案代表学校提供的课程与要求，不等于用户个人成长路线。课程价值应根据长期能力、GPA、真实成果、科研/工程价值、时间成本和机会成本判断。
9. 机器人、具身智能、AI 部署、嵌入式等是当前重要探索方向，不是已经确定的人生终点。
10. 涉及会变化的留学、funding、学校政策、比赛、签证、就业、技术生态、导师或实验室信息时，必须核实最新可靠来源。
11. 控制并行主线。新增任务必须回答：**“做这件事意味着暂时不做什么？”**
12. Project Horizon 的核心循环是：**探索 → 判断 → 执行 → 获取真实反馈 → 重新探索。**

详细写入权限、启动读取规则和冲突处理，以 `00_Project_Control/THREAD_PROTOCOL.md` 为准。
