# Project Horizon Charter

This directory contains the constitutional and thread-startup documents of Project Horizon.

The Charter is the highest stable governance document. It defines the mission, durable principles, authority boundaries and decision model. It is intentionally separated from current priorities, weekly tasks, technical milestones and strategic hypotheses so that the project can evolve without rewriting its constitution every time reality changes.

## Governance Hierarchy

Project Horizon distinguishes stable governance from dynamic state:

1. **Charter** — mission, durable principles and authority boundaries.
2. **Operational protocol** — `../00_Project_Control/THREAD_PROTOCOL.md`.
3. **Current control state** — `../00_Project_Control/MASTER_STATUS.md`.
4. **Strategic exploration** — `../00_Strategy/Voyage_Room/`.
5. **Specialist execution state** — each domain's `STATUS.md`.
6. **Evidence** — code, projects, experiments, competition results, research outputs and other verifiable artifacts.

Chat memory is supporting context only. When current chat memory conflicts with formal GitHub state, GitHub governs.

## Three-Layer Operating Model

- **Voyage Room / 远航室 = Explore**
- **Main Control / 主控 = Decide & Coordinate**
- **Specialist Threads / 专业线程 = Execute**

The Voyage Room may challenge the current route and keep competing hypotheses alive, but it has advisory rather than execution authority. Main Control converts strategic exploration into resource decisions. Specialist threads execute approved learning and projects.

## When the Charter Should Change

The Charter should change rarely. Appropriate triggers include:

- a genuine change to the mission or durable values;
- a repeated governance failure showing that an authority rule is missing or ambiguous;
- a material change to the Project Horizon operating model;
- long-term evidence showing that a supposedly stable principle should be revised.

Current priorities, specific competitions, countries being researched, software versions, individual course choices and weekly plans belong in lower-level documents rather than the Charter.
