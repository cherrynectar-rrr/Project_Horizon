# Project Horizon Chat Thread Starter Pack

**Version 1.0 — Charter v2.0 Companion**  
**Effective date:** 2026 年 7 月 28 日

> 本文件是 `Project_Horizon_Charter_v2.0` 的执行配套文件。它不修改宪章，只把多线程治理规则转化为可直接复制的聊天启动说明。

## 1. 当前总控决定

依据 Charter v2.0 的“一条主线、最多两条支持线、少量维护线”规则，当前建议如下：

| 线程 | 状态 | 当前作用 |
|---|---|---|
| 00 - 总控 | 已激活 | 维护全局路线与复盘 |
| 01 - Python | 已激活 / 当前主线 | 完成 Student Manager V2 与 Python 工程基础 |
| 03 - Linux | 已激活 / 支持线 | 建立开发与系统基础 |
| 02 - C++ & Algorithm | 可激活 / 支持线 | 当前以 C++ 入门为主，算法只作辅助 |
| 08 - English | 可选维护线 | 低强度长期复利，不抢主线 |
| 04 - Embedded | 暂缓 | 等待 C/C++、Linux 与硬件条件 |
| 05 - Algorithm 独立 | 暂缓 | 等待 C++ 与联合线程达到拆分条件 |
| 06 - AI | 暂缓 | 等待 Python 工程与数学基础 |
| 07 - Robotics & Embodied AI | 暂缓 | 等待 C++、Linux、ROS2 前置 |
| 09 - Career | 按实习节点激活 | 需要求职或作品集转化时 |
| 10 - Graduate | 按申请节点激活 | 需要系统研究与执行时 |
| 11 - Investment | 后期低优先级 | 有稳定现金流且不分散主线时 |

**重要：** 不要一次性启动所有聊天。创建一个聊天不等于激活一条学习路线。当前技术主线仍是 Python；Linux 与 C++ 只能作为受控支持线。

## 2. 使用方法

1. 将 `Project_Horizon_Charter_v2.0` 放在同一 Project 的文件区，或在新聊天中附上该文件。
2. 使用与仓库目录一致的聊天名称。
3. 复制对应的完整启动说明作为第一条消息。
4. 新聊天回复后，只接受一个当前目标和一个最小任务；若它一次开启大量路线，要求它按本启动说明收缩。
5. 每次跨线程或重大决策，都回到总控。

## 8. 线程生命周期检查

- **创建：** 责任已变成活跃、重复且独立的工作。
- **继续合并：** 一个主题仍主要服务另一个主题，独立上下文很少。
- **拆分：** 目标、输出、术语和复盘节奏已独立，或历史难以查找。
- **暂停：** 缺少前置能力、时间、预算或战略时机。
- **归档：** 目标完成、过时或被其他线程吸收；保留最终状态和交接说明。

**责任测试：** 一个线程若无法说清“一个职责、一个当前目标、一个预期输出”，就说明范围过宽或尚不该存在。
