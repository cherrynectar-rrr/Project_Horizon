# Project Horizon

Project Horizon is a long-term personal development and engineering-capability system.

> **Mission:** Build world-class engineering, research and judgment capability to earn the freedom to choose how to live, where to live and why to work.

## Operating Model

Project Horizon uses two layers:

- **Horizon Core / 核心舱 = Explore + Decide & Coordinate**
- **Specialist Threads = Execute**

The former Voyage Room / Main Control split is retired. Strategic exploration survives as Horizon Core's internal **Explore** mode.

## This Repository's Role

`cherrynectar-rrr/Project_Horizon` is now the **control plane** of a multi-repository ecosystem.

It owns:

- Charter and governance;
- `MASTER_STATUS.md`;
- `THREAD_PROTOCOL.md`;
- long-term strategy and Core decisions;
- cross-repository ownership / coordination;
- migration and architecture records.

Detailed technical learning, project implementation, academic operations and life operations live in dedicated repositories.

## Learning / Evidence Philosophy

Horizon prefers:

- durable capability over superficial activity;
- self-study plus assessment by default;
- real projects and experiments;
- debugging and testing as engineering habits;
- runnable / explainable / reproducible evidence;
- one main technical line with deliberately bounded support;
- opportunity-cost awareness;
- current reliable sources for mutable external facts.

Courses, competitions, certificates and projects are tools, not personal identity or automatic priorities.

## Human-Only Showcase Boundary

The user's personal showcase/profile repositories are **Human-only / Manual-only**.

Horizon agents do not read, edit, review, synchronize or write to those repositories unless the user explicitly revokes that boundary.

Horizon produces genuine work in Horizon-owned repositories. The user alone decides what to present publicly in personal showcase spaces.
